# СМР-Про: Система интеллектуального поиска расценок

Микросервисная реализация четырёхслойной системы интеллектуального поиска
строительных расценок с адаптивной базой знаний на основе анализа
исторических смет.

## Куда класть данные

Система использует две раздельные БД:

| БД | Назначение | Где хранится |
|---|---|---|
| **Ваша SMR-Pro SQLite** | каталог (Rates, Materials, Mechanisms, Devices + RateGroups) | `data/raw/smr_catalog.db` *(положите сюда)* |
| **Наша SQLite** (`smr_pro.db`) | поисковый индекс + база знаний (транзакции, ассоциации, профили, feedback) | `data/smr_pro.db` *(генерируется)* |

```
data/
├── raw/
│   ├── smr_catalog.db    ← ваш SMR-Pro каталог (read-only источник)
│   ├── estimate_01.xml   ← XML файлы со сметами
│   ├── estimate_02.xml   ← можно класть сколько угодно
│   ├── 2024/             ← или организовать в подпапки
│   │   ├── Q1/
│   │   │   └── project_a.xml
│   │   └── Q2/
│   │       └── project_b.xml
│   └── 2025/
│       └── project_c.xml
├── smr_pro.db             ← создаётся импортом
├── models/                ← FastText, SBERT, CatBoost (генерируются)
└── indices/               ← BM25, FAISS (генерируются)
```

Сканирование `data/raw/` **рекурсивное** — кладите столько XML, сколько нужно, в любую вложенность. Парсер потоковый (`lxml.iterparse`), поэтому работает даже с очень крупными файлами без перерасхода памяти. Повторный запуск ингестии безопасен: транзакции дедуплицируются по хешу набора кодов расценок.

### Маппинг источника в нашу схему

| Ваша таблица | `rascenka.entity_type` | XML `tip` |
|---|---|---|
| `Rates`       | `'rate'`      | `100` |
| `Materials`   | `'material'`  | `101` |
| `Mechanisms`  | `'mechanism'` | `103` |
| `Devices`     | `'device'`    | — |

Для расценок дополнительно сохраняется `RateGroupId`, что позволяет ранжированию учитывать иерархию (см. ниже).

### Иерархический поиск по группам расценок

Вы предложили сначала искать по группам — в системе это сделано через **обогащение текста индексации**: при построении BM25/FAISS индексов к названию расценки добавляется название её родительской `RateGroup` (с префиксом и вверх по иерархии). Например:

```
Окраска поливинилацетатными … стен  |  Малярные работы | Глава 15
```

Это даёт эффект двухуровневого поиска без отдельного сервиса:
- запрос «малярные работы» естественно подтягивает все расценки из этой группы;
- запрос с конкретным кодом или термином работает как раньше;
- материалы/механизмы (у них нет группы) индексируются только по своему названию.

При желании можно добавить и явный фильтр по `entity_type` или `rate_group_id` — обе функции уже поддерживаются `BM25Search.search()` и `SemanticSearch.search()` через параметры `entity_filter=` и `group_filter=`.

## Быстрый старт

### Вариант А: с вашей SMR-Pro БД (рекомендуется)

```bash
# 1. Установить зависимости
python -m venv venv && source venv/bin/activate
pip install -r requirements-dev.txt

# 2. Положить ваши данные в data/raw/
cp /path/to/your_smr_catalog.db   data/raw/smr_catalog.db
cp /path/to/historical_*.xml      data/raw/

# 3. Инициализация + импорт каталога + полный train в одну команду
make init
make import           # импорт из data/raw/smr_catalog.db
make train            # обучает всю базу знаний (~5–15 мин)

# 4. Запуск всех сервисов
make run
# открыть http://localhost:8080
```

`make train` сам подтянет каталог из `data/raw/smr_catalog.db` (если он там лежит) **и** разберёт XML-сметы в одном проходе — поэтому шаг `make import` можно опустить, если вы уже положили оба источника на место.

### Вариант Б: на синтетических данных (без вашей БД)

```bash
make install
make sample           # создаст data/raw/sample.xml с 7 ПТМ
make train       # быстрое обучение без SBERT/CatBoost  make
make run
```

## Микросервисы

| Сервис         | Порт  | Эндпоинт                  | Назначение                         |
|----------------|-------|---------------------------|------------------------------------|
| Preprocessing  | 5001  | `POST /preprocess`        | Нормализация и расширение запроса |
| Retrieval      | 5002  | `POST /retrieve`          | Гибридный поиск BM25+SBERT+RRF    |
| Ranking        | 5003  | `POST /rank`              | Переранжирование CatBoost          |
| Postprocessing | 5004  | `POST /postprocess`       | Формирование технологических комплектов |
| Gateway        | 5000  | `POST /search`            | Полный пайплайн                    |
| UI             | 8080  | `GET  /`                  | Веб-интерфейс                      |

## Технологии

- **Python 3.10+**, Flask
- **rank_bm25** – BM25 поиск (вместо Elasticsearch для простоты)
- **sentence-transformers** – SBERT эмбеддинги
- **faiss-cpu** – векторный индекс
- **mlxtend** – FP-Growth ассоциативные правила
- **catboost** – градиентный бустинг для LTR
- **natasha**, **pymorphy3** – морфология русского языка
- **symspellpy** – коррекция опечаток
- **SQLite** – хранилище данных
